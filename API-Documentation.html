Introduction

The E-Commerce API is a clean-architecture REST backend for an online store, built on .NET 9. It exposes catalog, basket (Redis), ordering, and identity modules, plus an Admin area guarded by role-based authorization (JWT).

.NET 9

ASP.NET Core Web API with minimal-program hosting and C# 13 primary constructors.

Entity Framework Core 9

Code-first migrations, specification pattern for querying, and JSON seeding.

Redis

Basket storage with TTL (30-day default) via StackExchange.Redis.

SQL Server

Relational store for products, orders, identity (ASP.NET Core Identity).

JWT Bearer

HS256-signed tokens, 7-day expiry, role claims (Admin / User).

AutoMapper 15

Object mapping with profiles; patched (15.1.1) for CVE-2026-32933.

Serilog

Structured logging — console + rolling daily file under Logs/.

Health Checks

DB-ping endpoint at GET /health.

Swagger

OpenAPI UI with Bearer security definition (development).

xUnit + Moq

15 unit tests covering services (product, basket, order).

Getting Started

Prerequisites

  • .NET SDK 9.0
  • SQL Server (or LocalDB) instance
  • Redis server (default localhost:6379)

Configuration (appsettings.json)

{
  "ConnectionStrings": {
    "DefaultConnection": "Server=(localdb)\\mssqllocaldb;Database=ECommerceDb;Trusted_Connection=True;",
    "Redis": "localhost:6379"
  },
  "JWT": {
    "SecretKey": "<your-256-bit-secret>",
    "Issuer": "https://localhost:7001",
    "Audience": "https://localhost:7001"
  },
  "BaseUrl": "https://localhost:7001"
}

Run

dotnet restore
dotnet ef database update --project Infrastructure/Persistence --startup-project E-Commerce
dotnet run --project E-Commerce

The startup initializer applies migrations and seeds data automatically. Swagger UI is available at /swagger in development. Seeded Admin role is created during initialization; assign a user to it via the admin users endpoints.

Architecture

The solution follows Clean Architecture: dependencies point inward. Domain defines entities and contracts; Services orchestrate business rules and mapping; Persistence implements EF Core + Redis; Presentation exposes HTTP; the host wires everything and hosts admin controllers.

  • Specification pattern keeps query logic reusable (ProductWithBrandAndTypeSpecifications, OrderWithItemsSpecification, …).
  • Generic repository + Unit of Work give a uniform data-access surface.
  • Global exception handler converts BusinessException and validation failures into ProblemDetails responses.
  • DTOs everywhere — entities are never serialized to clients except through mapped responses.

Authentication

Flow: POST /api/account/register or POST /api/account/login → returns a signed JWT. Send it as Authorization: Bearer <token>. Tokens live 7 days and carry nameid, email, given_name and role claims.

Route areaRequired auth
Account (register/login)Public
Products, BasketsPublic
Orders, /api/account/currentUserAuthorize — any role
/api/admin/**Authorize — Admin role

Note: production JWT settings (Issuer, Audience, SecretKey) must come from secure configuration and the secret should be ≥ 32 bytes.

Baskets · /api/baskets (Redis)

Public endpoints. Baskets are stored in Redis under the client-supplied id (typically a GUID generated client-side) with a default TTL of 30 days. Non-positive TTLs fall back to the default.

GET/api/baskets?id={id}

Returns BasketDto or 404 BasketNotFound.

POST/api/baskets

Create or replace a basket. Request body BasketDto:

{
  "id": "a5c9-…",
  "basketItems": [{
    "id": 1, "productName": "Air Jordan", "pictureUrl": "…",
    "price": 120.50, "quantity": 2
  }]
}

Note: the API stores the basket as-is and does not re-validate prices against the catalog at write time.

DELETE/api/baskets/{id}

Removes the key. Returns 204.

Orders · /api/orders

Requires JWT (any authenticated user; buyer email is taken from the token).

GET/api/orders

Orders for the current user (OrderDto[]).

GET/api/orders/{id}

Order by id — only if it belongs to the current user; otherwise 404 OrderNotFound.

POST/api/orders

Place an order from an existing basket. Request body CreateOrderDto:

{
  "basketId": "a5c9-…",
  "deliveryMethodId": 2,
  "shippingAddress": {
    "firstName": "John", "lastName": "Doe", "street": "Main St 1",
    "city": "Cairo", "state": "Cairo", "zipCode": "12345"
  }
}
  • Prices are copied from the catalog (not the basket).
  • Basket items without a matching product are skipped.
  • Subtotal = Σ (price × quantity); Total = Subtotal + delivery price.
  • Order is created with status Pending, then the basket is deleted.
{
  "id": 1, "buyerEmail": "john@example.com", "orderDate": "2026-08-10T…",
  "deliveryMethod": "DHL", "deliveryPrice": 5, "subtotal": 241.0, "total": 246.0,
  "status": "Pending", "orderItems": [ … ]
}

GET/api/orders/deliveryMethods

Available delivery methods (DeliveryMethodDto[]).

Account · /api/account

POST/api/account/register

Create an account (role User auto-assigned) and receive a token.

POST /api/account/register
{ "displayName": "John", "email": "john@example.com", "password": "Passw0rd!" }

Response — AuthResponseDto:

{ "id": "…", "email": "john@example.com", "displayName": "John",
  "token": "eyJhbGciOi…", "roles": ["User"] }

POST/api/account/login

Sign in (LoginDto: email, password). Failed attempts use Identity lockout. Invalid credentials → 401 InvalidCredentials.

GET/api/account/currentUser

Authorize. Refreshed user info + fresh token.

Admin · Products · /api/admin/products

Requires Admin role.

GET/api/admin/products

All products (first page, default paging).

POST/api/admin/products

Create product (ProductUpsertDto: name, description, pictureUrl, price, brandId, typeId). Returns 201.

PUT/api/admin/products/{id}

Update product. 404 if not found, 204 on success.

DELETE/api/admin/products/{id}

Delete product. 404 if not found, 204 on success.

Admin · Orders · /api/admin/orders

Requires Admin role.

GET/api/admin/orders?email={email}

All orders, or filtered by a buyer email.

PUT/api/admin/orders/{id}/status

Update order status. Body is a raw OrderStatus enum string:

PUT /api/admin/orders/1/status
"Shipped"

Statuses: Pending, PaymentReceived, PaymentFailed, Shipped, Delivered, Cancelled.

Health & Observability

GET/health

Liveness/readiness probe that pings the SQL database via EF Core:

{
  "status": "Healthy",
  "results": { "E-Commerce_DbContext": { "status": "Healthy", "duration": "00:00:00.03" } }
}

Logging: Serilog writes structured logs to the console and to rolling daily files at Logs/api-YYYYMMDD.log. Global exception handler + AddProblemDetails produce RFC 7807 error responses for all API failures.

Error Handling

Failures are returned as application/problem+json:

{
  "type": "https://tools.ietf.org/html/rfc9110#section-15.5.1",
  "title": "Product with id 99 not found",
  "status": 404,
  "traceId": "…",
  "errors": { "errorCode": "ProductNotFound" }
}
