3. Authentication Flow

3.1 Registration

POST /api/account/register → RegisterDto → Check Duplicate Email → Create AppUser → Assign "User" Role → Generate JWT Token → Return AuthResponseDto

3.2 Login

POST /api/account/login → LoginDto → Find by Email → Check Password → Generate JWT Token → Return AuthResponseDto

3.3 JWT Token Structure

Claims:
  - NameIdentifier  = User.Id
  - Email           = User.Email
  - GivenName       = User.DisplayName
  - Roles           = User Roles (list)

Signed with: HMAC-SHA256 (SymmetricSecurityKey)
  Secret Key: from JWT:SecretKey in appsettings.json
  Valid Issuer: https://localhost:7228
  Valid Audience: https://localhost:7228
  Expiration: 7 days

3.4 How to Use

Register: POST /api/account/register with { displayName, email, password }
Login: POST /api/account/login with { email, password }
Use Token: Add header Authorization: Bearer <token> to authenticated requests

3.5 Get Current User

GET /api/account/currentUser → [Authorize] → Extract userId from JWT → Return AuthResponseDto

5. Complete Business Flows

5.1 Full Shopping Flow (User)

Step 1: Browse Products GET /api/product?brandId=&typeId=&sortBy=&search=&pageIndex=1&pageSize=10 GET /api/product/brands (get all brands for filter dropdown) GET /api/product/types (get all types for filter dropdown) GET /api/product/{id} (view single product detail) Step 2: Manage Basket (Redis - no auth required) POST /baskets { id: "unique-basket-id", basketItems: [...] } GET /baskets?id=unique-basket-id DEL /baskets/{id} Step 3: Register / Login (if not already authenticated) POST /api/account/register { displayName, email, password } POST /api/account/login { email, password } Response contains: { id, email, displayName, token, roles } Save the token for subsequent requests. Step 4: Choose Delivery Method GET /api/orders/deliveryMethods Response: [{ id, shortName, description, deliveryTime, price }] Example: UPS1 ($10, 1-2 Days), FREE ($0, 1-2 Weeks) Step 5: Create Order POST /api/orders?email=user@example.com { basketId: "unique-basket-id", deliveryMethodId: 1, shippingAddress: { firstName: "John", lastName: "Doe", street: "123 Main St", city: "New York", state: "NY", zipCode: "10001" } } System automatically: - Retrieves basket from Redis - Validates delivery method - Looks up product prices from DB - Calculates subtotal - Sets status to Pending - Deletes the basket from Redis - Returns OrderDto with Total Step 6: View Orders GET /api/orders?email=user@example.com GET /api/orders/1?email=user@example.com

5.2 Admin Flow

Step 1: Login as Admin POST /api/account/login { email: "admin@ecommerce.com", password: "Admin@123" } Step 2: Manage Users GET /api/admin/users (view all users) GET /api/admin/users/{id} (view single user) POST /api/admin/users/{id}/roles "Admin" (assign role) DEL /api/admin/users/{id}/roles "User" (remove role) POST /api/admin/users/{id}/lockout (toggle lockout) DEL /api/admin/users/{id} (delete user) Step 3: Manage Products GET /api/admin/products (view all products) POST /api/admin/products { ... product } (create product) PUT /api/admin/products/1 { ... product } (update product) DEL /api/admin/products/1 (delete product) Step 4: Manage Orders GET /api/admin/orders (view all orders) GET /api/admin/orders?email=user@test.com (filter by user) PUT /api/admin/orders/1/status "Shipped" (update order status)

6. Error Handling System

6.1 Global Exception Handler

The API uses .NET 8+ built-in IExceptionHandler registered via AddExceptionHandler<GlobalExceptionHandler>(). All errors return a uniform ApiResponse format.

Response Format

// Success Response (returned directly by controllers, NOT wrapped)
{ data: ..., message: "..." }

// Error Response (returned by exception handler or validation)
{
  message: "...",
  errors: [
    { code: "NotFound", description: "Product with ID 5 was not found.", field: null }
  ]
}

How to Throw Business Exceptions

// In any service:
throw new BusinessException(BusinessErrorCode.ProductNotFound, $"Product with ID {id} was not found.");
throw new BusinessException(BusinessErrorCode.EmailAlreadyRegistered, "This email is already registered.");
throw new BusinessException(BusinessErrorCode.InvalidCredentials, "Invalid email or password.");

Model Validation Errors

When request body validation fails (via [Required], [EmailAddress], etc.), the API returns:

{
  message: "Validation failed",
  errors: [
    { code: "ValidationError", description: "The Email field is required.", field: "Email" },
    { code: "ValidationError", description: "The Password field is required.", field: "Password" }
  ]
}
